# Render Deployment

## Option A. Blueprint

This repository includes `render.yaml`.

In Render, choose `New -> Blueprint` and select this GitHub repository. Render can create the Web Service and PostgreSQL database together.

Render will ask for these values during blueprint setup:

```bash
ADMIN_USERNAME
ADMIN_PASSWORD
USER_USERNAME
USER_PASSWORD
```

If you do not want to create a regular user during the first deploy, leave `USER_USERNAME` and `USER_PASSWORD` empty.

`DATABASE_URL` is provided by Render PostgreSQL automatically, and `SECRET_KEY` is generated by Render.

## Option B. Manual Setup

### 1. PostgreSQL

Create a PostgreSQL database in Render and copy the connection URL from the Connect menu.

Set it on the Web Service as:

```bash
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME
```

If Render shows a `postgres://...` URL, the app converts it to `postgresql://...` automatically.

### 2. Web Service

In Render, choose `New -> Web Service` and connect this GitHub repository.

Build Command:

```bash
pip install -r requirements.txt
```

Start Command:

```bash
gunicorn app:app
```

### 3. Environment Variables

Add these variables in the Web Service Environment page:

```bash
DATABASE_URL=your Render PostgreSQL connection URL
SECRET_KEY=a long random string
FLASK_ENV=production
ADMIN_USERNAME=admin
ADMIN_PASSWORD=a strong password
```

Only add these if you want to create a regular user during first startup:

```bash
USER_USERNAME=staff
USER_PASSWORD=a strong password
```

## First Deploy

No manual database command is required.

On first startup, the app automatically:

- Creates the required database tables
- Creates the initial admin from `ADMIN_USERNAME` and `ADMIN_PASSWORD`
- Does not import sample data
- Does not delete existing data

## Smoke Test

After Render gives you the service URL, test the app in this order:

1. Open `/inventory` while logged out and confirm it redirects to `/login`
2. Log in as the admin user
3. Log in as the regular user, if one was created
4. Confirm the regular user can view, search, add, edit, receive, and ship inventory
5. Confirm the regular user can use stocktaking and edit recent inventory activity
6. Confirm the regular user cannot access Excel import, Excel export, or user management
7. Confirm the admin user can upload an Excel file
8. Confirm the uploaded inventory appears in the inventory list
9. Confirm zero-stock reminders appear correctly
10. Confirm low-stock reminders appear correctly
11. Confirm the site works from a phone or an outside network
